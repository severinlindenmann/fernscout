# B199 — One accessible name carrying two things

## Why

Noticed while verifying B79 on the live site, in the neighbouring block rather
than in B79's own. The `CopyLine` in the agent-handover section of
`/<user>/me` carries:

```
aria-label="Copy link: https://fernscout.ch/documentation.txt\nxydhd-qa1@severin.io"
```

Two separate values — the documentation URL and the owner's address — joined by
an embedded newline, inside a single accessible name.

Visually this block is right, and B75 verified the sighted version: two lines,
clearly the pair of things an owner hands to an agent. The accessible name is
where the pairing falls apart. A screen reader announces one run of text with
no boundary between the two, so a URL and an email address arrive as one
string, and "Copy link" describes a control that copies both. Newlines in an
accessible name are not reliably announced as a break — the behaviour varies by
reader — so the listener gets no cue that there were ever two values.

The stakes are small and specific: this is the one control on the page whose
whole purpose is to hand two exact strings to somebody else, and it is the
first thing the owner of a new journal is pointed at. Getting one string where
there were two is a real way to be confused about what was copied.

## Work

- Give the control an accessible name that describes what it copies rather than
  reciting it — "Copy the two lines to hand an agent" or similar — and let the
  values be read from the visible text, which is already correctly marked up.
- If the values should be in the name, make it one value per control: two
  `CopyLine`s, each naming what it holds.
- Check the other `CopyLine` uses while in there. B79's invite panel uses the
  same component with a single value and is fine, but that is the only other
  caller and it is worth confirming it stays that way.

Not doing: changing the visible layout. B75 verified it and it reads well.

## Acceptance

- No accessible name on the page contains an embedded newline.
- The handover control's name says what it copies; the values are reachable as
  page text.
- The invite panel's copy control is unaffected.

## What changed

The first option in **Work**: the control is named for what it copies, and the
values stay on the page as text.

- `components/CopyLine.tsx` takes an optional `name`. Absent — which is every
  caller but one — the accessible name is `"<label>: <value>"`, unchanged.
- `components/AgentHandover.tsx` passes `name={t("me.agentCopy")}`.
- `me.agentCopy` is a new key in all three shipped dictionaries, with
  `lib/i18n.ts` regenerated by `npm run i18n:keys`. English:
  *"Copy both lines: the guide’s address, and the address a code is sent to"*.

Two `CopyLine`s was the other option and was rejected: the block hands over one
thing — the pair — and splitting the control would mean two clipboard actions
where the instruction above it says "hand these two lines to an agent". The
visible layout is untouched, as the ticket asks.

**The other callers were checked, as Work asked.** There are two, not one:
`components/InviteLinks.tsx` (a single invite URL) and `components/Landing.tsx`
(the instance's `documentation.txt` address). Both hold one value, both recite
it, and both are unaffected — the invite panel's name is asserted in the test
below so it stays that way.

## Evidence

`test/copy-line-name.test.tsx` — new, 4 tests. Against the code as it was:

```
× names what it copies instead of reciting two values
    AssertionError: expected [ 'Copy link: https://…/documentation.txt\nowner@example.test' ]
    to include 'Copy both lines: the guide’s address, …'
× no accessible name on the block carries a newline
    AssertionError: expected 'Copy link: https://fernscout.ch/docum…' not to match /[\n\r]|&#10;|&#xa;/i
```

One existing test had to move with it. `test/empty-journal.test.tsx` asserted
"the copy button carries both lines at once" by looking for
`<doc-url>\n<email>` in the markup — which was only findable there *because*
the two values were inside the accessible name. The property is still worth
holding, so it is now asserted through the control's name, with the clipboard
half held by the new test.

The second failure above is the acceptance line, and it failed on exactly the
string the ticket quotes. The other two cases: the name is translated in all three
maintained locales rather than English on a journal that is not, and the invite
panel's single-value control still announces `"Copy link: <url>"`.
