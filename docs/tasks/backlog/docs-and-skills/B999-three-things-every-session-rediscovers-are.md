# B999 — Three things every session rediscovers are not written down

## Why

Read across the sixteen session transcripts of 2026-09-07 and 08 (about 38,700
Bash calls), three things cost time in every one of them and are written down
nowhere an agent will find them.

**The sign-in mail.** `.claude/skills/test-in-a-browser/SKILL.md:90` sent
agents to `content/<user>/mail/`, which has not been where mail lands since
B636 — `lib/mail/index.ts:91` puts it under `<dataDir>/mail/<user>/`. Four
sessions searched the old path, then `.local-dev-data/`, then gave up and ran
`find . .. ../../.. -name '*.eml'`. The whole section was also unnecessary:
`lib/auth/index.ts:200` honours `AUTH_DEV_CODE`, which fixes the code outright
and which `docs/qa/SCENARIOS.md` was already using.

**`npm ci` in a worktree.** AGENTS.md told agents to run it; it was run 65
times in that week, minutes each. `cp -Rc` from the main checkout is an APFS
copy-on-write clone, about eight seconds and no real disk. A symlink is the
obvious wrong answer and was tried again on 09-08 — Turbopack refuses it with
*"Symlink [project]/node_modules is invalid, it points out of the filesystem
root"*, so `verify` fails at the build for a reason unrelated to the change.

**A new UI string.** `site/locales/{en,de,hu}.json` plus the `TranslationKey`
union in `lib/i18n.ts`, regenerated by `npm run i18n:keys`. Two tests enforce
it (`test/locales.test.ts:104` and `:440`) and no document mentions the script,
so it is found by tripping over `tsc`.

Separately, the persona method — the owner's most-repeated instruction of the
week, asked for in his own words at least five times — existed only inside
`docs/plans/2026-09-07-helper-everything.md`, which AGENTS.md says is intent
recorded before the work and must never be corrected. So the one durable
procedure in it was unreachable and un-updatable.

## Work

- `.claude/skills/test-in-a-browser/SKILL.md` — `AUTH_DEV_CODE` in the dev
  server block; correct the mail path and say what it was before B636.
- `AGENTS.md` — `cp -Rc` in the worktree recipe and in the note beneath it,
  with why a symlink fails; a short section on adding a UI string; a row for
  the new skill.
- `.claude/skills/test-with-personas/SKILL.md` — new. The personas, the
  `severin.io` address convention, reading the code on the VPS and locally,
  and the rule the last rounds broke: a finding is a `backlog/` id, not a
  paragraph, and a persona that could not finish is a failed round.

Not doing: no hook, no test. These are three documents telling the truth
again, and a test that asserts prose is a test that fails on a rewording.
`lib/i18n.ts` was left with its union unsorted — regenerating it is cosmetic,
the test compares sorted, and the file is inside another session's in-flight
merge.

## Acceptance

- `grep -n "content/<user>/mail" .claude/skills/test-in-a-browser/SKILL.md`
  finds nothing but the sentence saying that is where it used to be.
- A fresh worktree set up by following AGENTS.md gets through
  `npm run verify` without `npm ci`.
- `npm run verify` passes.
- A person reads `test-with-personas` and can run a round from it without
  asking anything.
