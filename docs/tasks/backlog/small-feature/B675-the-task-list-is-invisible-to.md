# B675 — The task list is invisible to anybody not standing in the checkout

## Why

Six hundred and thirty tasks across five lanes say what this software is,
what is wrong with it and what is coming — and every word is in `docs/tasks/`,
readable only by someone with the checkout open. Anybody looking at the
running site, deciding whether to host their own, has `/docs` and no idea
whether the thing they need is planned, refused or already merged and waiting
for a person to try it.

`INDEX.md` is already generated by `npm run tasks`, so the data is structured
and current. What is missing is a reading of it that a person outside the
repository can open.

## Work

A page under `/docs` that renders the task tree at build time — the lanes as
the shape of it, since the lane *is* the status. Read the files the way
`lib/docs.ts` reads the rest of `docs/`; nothing new is stored and nothing is
written back.

Decisions:

- **What is shown.** Title, id, type, priority, lane. Probably not the bodies —
  they name files, they argue with themselves, and several are security
  findings.
- **Security is the one that has to be got right.** `docs/tasks/backlog/security/`
  describes live weaknesses in a running instance. Either that folder is
  excluded outright, or nothing is published until somebody reads all of it.
  Excluded is the lazy answer and the safe one.
- **Not a status board.** It is generated from the same files at build time;
  there is no writing, no filtering UI, no per-task page unless a body turns
  out to be worth showing.

Not doing: a public issue tracker, comments, or anything that lets a reader
add to the list. `/documentation.txt` is where an agent already learns what
this instance is; this is for a person.

## Acceptance

`/docs/roadmap` lists the tasks by lane, generated from `docs/tasks/`, with no
`SECURITY` task on it and no task body that names a file path in a way that
teaches somebody where to push. It builds on an instance whose checkout has
tasks and renders as empty rather than failing on one that does not.
